# Xでのリプライ宣伝(princess-tower)

`@princess_tower8`から、クラロワのランキング系投稿に**リプライ(返信)**でサイトを紹介する。
リポスト・引用ではなく返信であること、**投稿直前に必ずユーザーの最終確認を取る**ことが前提(2026-09-22にユーザーが指示)。

このサイトの最大の差別化は「**タグを知らなくても名前でプレイヤーを検索できる**」点なので、
リプライには必ず**相手本人のプレイヤー詳細ページのリンク**を載せ、ただの宣伝文にしない。

**⚠ リンク付きの宣伝リプライは、個人・クリエイター宛てを合わせて1日3件までにする**(2026-09-28にユーザーが1件から変更)。2026-09-27に「宣伝リプライは件数を絞る」方針で1件にしていた(自分の返信は数十回しか見られず反応も0件で、件数を増やすとスパム扱いされる危険が増えるため。`X運用記録.md`の「反響の分析」)。露出を増やすのは引き続き`x-official-reply`スキルでの、リンクなしの返信を優先する。

## 手順

### 1. 候補をXで検索する

ブラウザツール(`claude-in-chrome`)で以下を開く。`f=live`が最新順、`f=top`が人気順。

```
https://x.com/search?q=%23クラロワ ランキング&f=live
https://x.com/search?q=%23ClashRoyale ranking&f=live
https://x.com/search?q=%23ClashRoyale ranking&f=top
```

- 日本語の`#クラロワ ランキング`は**件数が少なく数週間前の投稿しか出ないことが多い**。英語・スペイン語圏の方が母数が大きい。
- **複合語クエリで足りないときは`#クラロワ`単体のLatestを見る**。数十分〜数時間前の投稿が並び鮮度が圧倒的に高い(2026-09-21の実測)。日本語圏は質問ではなく「トロ13000行った」「26000勝」のような**実績報告**が主流なので、ランキング以外でもこの型は本人特定ができて相性がよい。
- **候補探しは毎回、日本語(`#クラロワ`)と英語(`#ClashRoyale`)の両方のハッシュタグで行う**(2026-09-24にユーザーが指示)。`#ClashRoyale`単体のLatest(`https://x.com/search?q=%23ClashRoyale&f=live`)も`#クラロワ`と同様に見て、英語圏の候補には`?lang=en`で返す。
- **ハッシュタグで見つからないときは`url:link.clashroyale.com since:<日付>`も見る**(2026-10-01に発見)。ゲームのフレンド・クラン招待リンク付きの投稿だけが出て、リンクのURLにタグ(`tag=CY0JY2QY`)が入っているので本人特定が確実。言語を問わず出るので、大型クリエイターの投稿が混ざることもある(10/1の23件目、11.8K)。10/3は`-filter:replies`を付けると「Something went wrong」で何も出ず、外すと出た(返信が混ざるので目で除く)。
- **`#クラロワ since:<日付>`の人気順(`f=top`)も見る**。10/3は、最新順では流れていた表示1.6Kの到達報告がここで見つかった(26件目)。
- `get_page_text`は先頭1件しか拾えないことがある。**スクリーンショットを撮ってスクロールしながら読む**のが確実。一覧をまとめて読むなら、`javascript_tool`で`article[data-testid="tweet"]`ごとに日時(`time`)・本文(`[data-testid="tweetText"]`)・表示回数(`a[href$="/analytics"]`の`aria-label`)を抜き出し、スクロールのたびに追記していく(10/3)。
- 投稿のURLは`find`ツールで「投稿の日時リンク(status permalink)」を探すとまとめて取れる。

**必須条件: 表示回数(Views)が1,000回以上の投稿に限る**(2026-09-22にユーザーが決定)

リプライは1日数件までに抑える前提なので、**その少ない枠を誰にも見られない投稿に使わない**ため。

⚠ **ただしこの基準は「本人を特定できること」と実質両立しない**(2026-09-22に日英西葡の4言語で調査して確認。`X運用記録.md`の「分かったこと」参照)。

| 層 | 表示回数 | 判定 |
|---|---|---|
| 公式・esports組織 | 5K〜60K | 避ける候補に該当して使えない |
| 大型クリエイター・配信者 | 1K〜60K | **2026-09-26から候補に含める**(下の「大型クリエイターへの返信」参照) |
| **個人プレイヤー** | **26〜600程度** | 本人特定はできるが1,000回に届かない |

**着手したら、まずどちらを優先するかユーザーに確認する**(基準を下げて本人ページ付きで返すか、リーチ優先でリンクなしにするか)。2026-09-22は**質(本人ページを貼れること)を優先**する判断だった。探し続けても両立する候補は出てこないので、時間をかけすぎない。

- 検索結果の一覧では、各投稿の下部にある**棒グラフのアイコンの横の数字が表示回数**(`139`・`2.6K`・`15K`など)。ここで1,000未満を先に落とせば、投稿を1件ずつ開かずに絞り込める
- 投稿の詳細ページでは日時の横に`1,960 Views`の形で出る。**送信直前にこの数字を必ず確認する**
- `K`表記は千単位(`2.6K`=約2,600)。`1K`未満の表記(3桁の数字)はその場で除外する

**良い候補**(この順で優先)
- **フレンド募集の投稿**(「フレンド募集」「最近復帰した」など)。**プロフィール画像にプレイヤータグ・名前・戦績がそのまま写っていることが多く、本人特定が最も確実**(2026-09-22の実例では画像内のタグ`#VU9GCGUV9`と勝利数5,937がサイトの値と完全一致した)。相手の目的に寄せて「フレンドになった人のデッキを見るのにも使える」と書けるのも相性がよい
- 本人のランク・順位の報告(「○位に載ってた」「TOP 1 SPAIN」など)。祝意を述べたうえでリンクを出せるので、宣伝色が薄まる
- ランキングのスクリーンショットが貼られていて、**プレイヤー名が読み取れる**もの

**大型クリエイターへの返信(2026-09-26にユーザーが方針変更)**

それまでは「話題の乗っ取りに見える」として避けていたが、表示回数1,000回以上と本人特定を両立できるのは実質この層だけなので、**時々試して反応を見る**方針に変えた。
- 対象は**本人のプレイ内容の投稿**(対戦クリップ・デッキ・ランク到達など)。イベント攻略や告知、大会の案内など、プレイヤーページにつなげにくい投稿には返さない
- 本人のタグ・名前を必ず特定してから返す(ルールは個人と同じ。特定できなければ送らない)
- **1日3件まで**にする(2026-09-26に1件から変更。ユーザー判断)。人気の投稿の返信欄は多くの人が見るので、便乗の宣伝と受け取られて通報されやすく、アカウント全体がスパム扱いされる危険が個人宛てより大きい
- 文面は祝意やお世辞ではなく、**相手にメリットのある情報**を冒頭に出す(下の「3. リプライ文を作る」。本人の成績を言い直すだけではメリットにならない)
- 送信後は、元投稿の表示回数と、後日`access-check`で見た`?from=xreply`の件数を`X運用記録.md`に残し、個人宛てと効果を比べる

**避ける候補**
- 他のクラロワ統計サイト(`clashroyale.last-dragon.work`・`claroy.rakda3.net`・CRTracker等)の宣伝投稿。競合の投稿に自サイトを貼る形になる
- 公式・esportsのアカウント(クラロワ公式、CRL関連)の告知。話題を乗っ取る形になる(公式への**リンクなしのデータの返信**は別のやり方で、`x-official-reply`スキルで行う)
- カードの強さランキングなど、プレイヤーを特定できない投稿(リンクを出す口実がない)
- **返信を制限している投稿**(投稿詳細の返信欄の代わりに「Only some accounts can reply.」と出る)。**文面を作る前に確かめる**(2026-10-02に承認後に送れないと分かった)

### 2. 投稿者のプレイヤータグを特定する

**名前検索を先に試す**(`lang`は相手の言語に合わせる)。

**⚠ Git Bashから`curl`に日本語を渡すとCP932でエンコードされ、サーバーが400を返す**(`--data-urlencode`も同じ。2026-10-02に再発)。Pythonは引数を正しく受け取れるので、Pythonでエンコードした値を使う。

```bash
q=$(python -c "import urllib.parse,sys;print(urllib.parse.quote(sys.argv[1]))" "<プレイヤー名>")
curl -s "https://princess-tower.duckdns.org/player/search?q=$q&lang=ja" -o r.html
grep -oE 'href="/player/[0-9A-Z]{3,15}"|<bdi>[^<]+</bdi>' r.html
```

**⚠ 名前検索が空振りする主な原因**

- **ゲーム内の名前には全角記号が使われる**(`CR｜Malgret`の`｜`はU+FF5C)。記号の全角・半角の違いは検索側のNFKC正規化で吸収されるが、スクリーンショットの見た目から空白を補って`CR | Malgret`と入れると一致しない(2026-09-22に空振りした本当の原因。2026-09-27に確認)。`VosS シ`のように**カタカナが装飾記号として使われている**こともある。スクリーンショットの見た目だけで文字を決め打ちしない
- 検索は**完全一致＋前方一致**なので、`CR｜Malgret`に対して`Malgret`では引けない(先頭が`CR`のため)
- そもそも索引(929万件)に未収録の場合がある

**空振りしたらクラン経由で特定する**(この手順が最も確実)。プレイヤーカードのスクリーンショットにはたいていクラン名が写っている。

```bash
# 1) クラン名で検索してタグを得る(部分一致で大量に出るときは短いキーワードで絞る)
q=$(python -c "import urllib.parse,sys;print(urllib.parse.quote(sys.argv[1]))" "<クラン名>")
curl -s "https://princess-tower.duckdns.org/clan/search?q=$q&lang=ja" -o c.html
grep -oE '<bdi>[^<]+</bdi>|/clan/[0-9A-Z]{3,15}' c.html

# 2) メンバー一覧から本人を探す(全角記号込みの正確な名前もここで確認できる)
curl -s "https://princess-tower.duckdns.org/clan/<クランタグ>?lang=ja" -o m.html
grep -oE 'href="/player/[0-9A-Z]+"|<bdi>[^<]+</bdi>' m.html | grep -iB1 "<名前の一部>"
```

**同名が複数出た場合**(`VoSS`で3件など)は、どれが本人か決められないのでクラン経由に切り替える。
誤ったプレイヤーのリンクを貼るのは相手に失礼なので、**特定できなければリンクを載せない**(または候補から外す)。

最後に**リンクが実際に開けることを必ず確認する**。

```bash
curl -s "https://princess-tower.duckdns.org/player/<タグ>?lang=ja&from=xreply" -o p.html -w "HTTP %{http_code}\n"
grep -oE '<title>[^<]*</title>' p.html   # 名前が想定どおりか確認
```

### 3. リプライ文を作る

- **相手の言語で書く**。サイトは8言語対応なので`?lang=`も合わせる(`ja`/`en`/`es`/`pt`/`de`/`fr`/`it`/`ru`)
- **URLには必ず`?from=xreply`を付ける**(`?lang=es&from=xreply`のように連結)。自分の投稿は`?from=x`なので、**リプライ経由の流入を切り分けるために値を変えている**(2026-09-21に確立)。効果測定は`access-check`スキルでこの値を集計する
- **`&lang=`は必ず付ける**。付けないとOGPカードの説明文が英語で出る(Xのクローラーは`Accept-Language`を送らないためサイト既定の英語になる)。日本語の返信に英語の説明が付くのは不自然
- 構成は「①相手にメリットのある情報 → ②サイトの説明を一言 → ③本人のページのリンク → ④見られる内容＋非公式である旨」
- **①は、本人がすでに知っている自分の成績の言い直しにしない**(2026-09-30にユーザー指摘。「この試合から今日のランク戦は3連勝」を「プレイヤーに何のメリットもない情報」と差し戻された)。本人が次のプレイに使える情報にする。例: 本人のデッキの勝ち筋のカードを使う世界上位のデッキ(デッキ画面`/decks?card=<ID>`をカードで絞り込み、同じ組み合わせの人数と順位を数える。コピーボタンでそのまま試せる)。21件目の型
- **プレイヤーの「気付き」になるデータを入れた方が、リアクションが多い**(2026-09-30にユーザーの経験則として指示。絶対ではない)。「自分の型は上位に3人しかいない」「このカード相手だと負け越している」のように、本人が言われて初めて知る事実を選ぶ。どの切り口にも当てはまる決まりではないので、気付きになるデータが見つからないときは、無理に作らず役に立つ情報を優先する。ユーザーの見立てでは、フレンド募集・クラメン募集の人に特に刺さる(9/30)。サブ垢を当てるアイデアは`X運用記録.md`の「文面」に(本人が明かしている場合に限る)
- **本人の選択を否定するように読める数字は書かない**(2026-10-03にユーザー指摘)。ドリル＋バレルのデッキの人に「この型は世界上位1000人に0人でした」と書いた案は「不快に感じる」と差し戻された。少数派だと伝えてよいのは、本人がその型を自分で誇っているときだけ(26件目、プロフィールに「自作四銃士デッキしか使わない」とある人に「四銃士は世界上位に1人だけ」は承認)。迷ったら本人のデータを前向きに使う(28件目: 過去シーズンの最高2,190を今シーズン超えている→「自己ベスト更新ですね」)
- **文面を作る前に、Xのプロフィールも読む**。デッキのこだわりが書かれていることがある(26件目)。こだわりのカードを抜く提案(「マスケット銃士の代わりに〜」)にしない
- **募集の投稿には、募集に応じる側(候補)のメリットになる文章を入れる**(2026-09-30にユーザー指示)。クラメン募集ならクラメン候補(加入を考えている人)のメリット、フレンド募集ならフレンド候補のメリットにする。22件目(フレンド募集)は、本垢・サブ垢のページを両方リンクし、「申請する人が事前にデッキや強さを確かめられます」と書いて承認された。同じ返信の初稿「サブ垢のデッキと8枚同じ構成を世界上位の10人が使っている」は「これ誰のメリット？」と差し戻された(投稿の目的=仲間集めにつながらない豆知識だったため)
- 本垢とサブ垢など、リンクを複数付けたとき、Xのカードは1つ目のリンクのものが出た(22件目)。一番見てほしいページを先に置く
- プレイヤー情報画面の「苦手カード」は、モード・デッキを混ぜた直近の全対戦の集計。引用する前に対戦詳細で**今のランク戦のデッキでの対戦か**を確かめる(21件目では「エレクトロウィザード相手に2勝6敗」の8戦中5戦がチャレンジなど別デッキで、今のデッキでは0戦だった)
- **最後は「よろしければご利用ください！」で締める**(2026-09-28にユーザー指示)。日本語以外は同じ意味の一言にする(スペイン語なら「¡Úsala si te sirve!」)。280字に収まらなければ、この一文ではなく他の部分を削る
- **Supercellの非公式ファンサイトである旨を必ず入れる**(商標・ファンコンテンツポリシー対応。`archive/進捗ログ_2026-09.md`のフェーズ1.50)
- 文字数はXの上限280(日本語など全角は1文字=2)。URLは一律23文字として数える

日本語の例:
```
257位おめでとうございます🎉
名前でプレイヤーを検索できるサイトを作っていて、CR｜Malgretさんのページも出せます👇
https://princess-tower.duckdns.org/player/UJ9QP2RL8?lang=ja&from=xreply

使用中のデッキ・対戦履歴・連勝記録まで見られます(Supercell非公式のファンサイトです)
```

スペイン語の例:
```
¡Enhorabuena por el TOP 1 de España! 🇪🇸

Hago una web para buscar jugadores por nombre, sin la tag. Perfil de VosS シ 👇
https://princess-tower.duckdns.org/player/QC9YRJUR0?lang=es&from=xreply

Mazo actual, historial de batallas y rachas. Web de fans, no oficial.
```

### 4. ユーザーの最終確認を取る(必須)

元投稿の要約・**表示回数**・特定したプレイヤーとタグ・リプライ全文を提示し、`AskUserQuestion`で確認する。
**確認なしに送信しない。**

- **文面は2案ほど用意し、選択肢ごとの`preview`に全文と文字数を載せて選んでもらう**(2026-10-03にユーザー指示)。切り口(データが先/本人ページが先、など)を変えた案にする。10/3は本人ページが先の案が2件、データが先の案が1件選ばれた
- 候補が複数あるときは、1回の`AskUserQuestion`に候補ごとの質問を並べる(上限4問)。「送らない」も選択肢に入れる

あわせて伝えるべき注意点:
- **面識のない相手への宣伝リンク付きリプライは、件数が増えるとXにスパム判定されやすい**。1日数件程度に留める
- 元投稿が他アカウントを@メンションしている場合、**返信はそのアカウント全員に通知が飛ぶ**(実例: 8アカウント)。送信前に`Replying to ...`の表示を読んで件数を伝える

### 5. 送信する

元投稿のURLを開き、**ツイート詳細ページ下部のインライン「Post your reply」**を座標クリックして入力し、`Reply`を押す。
(投稿ダイアログを開く方式は使わない。インライン方式ではフォーカス喪失の誤爆が起きていない。)

**⚠ 過去にハマった点(`archive/進捗ログ_2026-09.md`のフェーズ1.55。ほかの操作の注意は`X運用記録.md`の「投稿の操作(ブラウザ)」)**

- **投稿欄にフォーカスが無い状態で文字を送ると、Xのキーボードショートカットとして解釈される**(`l`=いいね、`t`=リポストなどが誤爆する)。
  必ず①スクリーンショットで座標を確認してクリック →②**短い1語だけ入力してフォーカスを確認**(`Replying to @xxx`が出ているか)→③残りを流し込む、の順で進める
- 先頭に`¡`などの記号が要る言語では、フォーカス確認用の文字を打った後に`ctrl+a`で選択してから全文を入れ直すとよい
- **インラインの`Reply`は1クリックで送信できている**(2026-09-21・09-22とも)。一方、自分の投稿を出す**投稿ダイアログの`Post`は1回目が効かないことがある**。いずれも押下後は必ずスクリーンショットで`Your post was sent.`を確認し、出ていなければもう一度押す

### 6. 記録する

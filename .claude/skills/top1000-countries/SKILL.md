# 世界トップ1000人の国籍内訳

ランク戦のグローバル上位1000人が、どの国から何人出ているかを集計する。
**当サイトのデータだけで作れて、他所がまず出していない集計**なので、X投稿(`x-post`スキルの案21)のネタとしても使う。

## 肝: 公式APIに国籍フィールドは無いが、突き合わせれば確定できる

グローバルランキングのレスポンス(`PlayerRankingResponse.RankedPlayer`)は`tag`/`name`/`expLevel`/`eloRating`/`rank`/`clan`だけで**国籍を持たない**。
だが**国別ランキングは国ごとに独立して引ける**ので、次の突き合わせで国籍が確定する。

1. グローバル上位1000人のタグ集合を取る
2. 全254カ国それぞれの国別ランキングからタグ集合を取る
3. 両者の積集合の件数 = その国からトップ1000に入っている人数

**個別プレイヤーを1000件叩く必要はない**(254リクエストで済む)。
2026-09-22の実測では上位1000人**全員**がちょうど1カ国に紐づき、重複・取りこぼしともゼロだった。

## 実行

```bash
bash .claude/skills/top1000-countries/collect.sh <作業ディレクトリ>
```

- 作業ディレクトリはセッションのscratchpadを使う(中間ファイルが254カ国分できるため、リポジトリ内には置かない)
- **所要約3分**。254リクエストを0.4秒間隔で投げる(`SLEEP`環境変数で変更可能だが、**短くしすぎない**。本番VMは過去にクローラの高頻度アクセスで落ちたことがある)
- 第2引数に国コード一覧ファイルを渡すと対象を絞れる(動作確認用。例: `printf 'JP\nUS\n' > subset.txt`)
- 結果は`<作業ディレクトリ>/country_counts.tsv`(国コード / トップ1000人中の人数 / その国の登録総数)。標準出力に上位20カ国とサマリが出る

## 投稿・報告の前に必ず検証する

スクリプトが最後に出す4つの数字を確認する。**全カ国を対象にしたときは次が期待値**:

| 項目 | 期待値 | 外れていたら |
|---|---|---|
| マッチ総数 | 1000 | 取得漏れがある。`fetch_errors.txt`を見る |
| ユニーク | 1000 | 同上 |
| 2カ国以上に出たプレイヤー | 0 | 二重計上。合計が水増しされている |
| どの国にも出なかったプレイヤー | 0 | 国籍不明の取りこぼし。合計と割合が過小になる |

**数字が合わないまま投稿しない**。合わない場合は、そのぶんを「カバー率」として正直に書くか、取得し直す。

## 既知の結果(2026-09-22、比較用のベースライン)

| 国 | トップ1000人中 | その国の登録総数 |
|---|---|---|
| アメリカ | 99 | 1000 |
| 日本 | 79 | 1000 |
| ブラジル | 60 | 1000 |
| メキシコ | 59 | 1000 |
| ドイツ | 50 | 1000 |
| フランス | 48 | 1000 |
| イタリア | 39 | 1000 |
| 韓国 | 35 | 996 |
| カナダ | 32 | 729 |
| 中国 | 32 | 443 |

- 1人以上いる国は**85カ国**(調査対象254カ国中)、上位10カ国の合計は**533人**で半数を少し超える程度
- **数字は毎回取り直す**。同日中の再実行でも日本79→80人、香港21→20人と動いた(ランキングは常時変動している)

## 派生ネタ

- **登録人数あたりの上位進出率**: 香港は登録総数270人しかいないのに世界トップ1000に約20人と密度が突出している。国の規模ではなく「濃さ」を見る切り口(未実施)
- 「その国の登録総数」列は上限1000で頭打ちになる国が多いため、**総数どうしの比較は意味を持たない**(ここを主役にした投稿は2026-09-22にユーザーが「質が悪い」として削除した。`Xポスト案.md`の実施記録を参照)

# アクセス状況の確認(clash-royale-api)

このサイトはGPTBot・ClaudeBot等のAIクローラーと、Chromeを偽装した高度なスキャナーからの
トラフィックが大半を占める(2026-09-20時点で全体の99%以上)。「アクセスが少ない」と早合点したり、
逆にスキャナーを実訪問者と誤カウントしたりしないよう、必ず以下の手順で機械的な除外を通してから報告する。

## 手順

1. `scripts/check-access.sh`をBashツールで実行する(引数は省略可、省略時は今日のUTC日付)。
   ```
   bash "C:\dev\clash-royale-api\.claude\skills\access-check\scripts\check-access.sh"
   ```
   このスクリプトはVMにSSHし、以下をまとめて行う。
   - 日次集計スクリプト(`/usr/local/bin/clash-royale-access-stats.sh`、UA文字列ベースの簡易ボット除外)を最新の状態に再実行
   - それに加えて`references/known_noise.md`に載っている「UAは本物のブラウザに見えるが実は人間ではない」IP(既知のスキャナー・ユーザー本人の開発用IP)も除外
   - ページ別の内訳、深いページ(`/player/`・`/clan/`・`/cards`・`/ranking`・`/favorites`・`/card/`)への到達有無、X(Twitter)経由のリファラの有無を出力

2. 出力される「日次集計」の数字と「既知のノイズ除外後」の数字の**両方**をユーザーに示す。除外前の数字だけを「実アクセス」として報告すると、スキャナーを実訪問者として数えてしまい実態より楽観的な報告になる(2026-09-20に実際にこの間違いをした)。

3. 深いページへの到達が見つかった場合は、送信元IPをそのまま実訪問者と決めつけず、
   - 送信元がクラウド/データセンターのIP帯(Google `34.x`/`35.x`/`66.249.x`、AWS、DigitalOcean、Linode、Vultr等)でないか
   - 同じIPが短時間で全ページ種別を機械的に巡回していないか(スキャナーの典型パターン)
   を確認する。怪しければ「スキャナーの可能性が高い」と留保つきで報告し、断定はしない。

4. `references/known_noise.md`に載っていない新しいIPが「明らかに自動化された挙動」(例: `/.git/config`・クラウドのメタデータエンドポイントへの到達試行、全ページを秒単位で機械的に巡回)を示していたら、その場で`known_noise.md`に追記してよい。ただし「本当にユーザー本人のアクセスか」は紛らわしい場合があるので(2026-09-20に一度誤判定した経緯がある)、判断に迷うIPは除外せずユーザーに確認する。

5. ユーザー自身の開発用IP(`known_noise.md`参照)は固定でない可能性があるため(`CLAUDE.md`のAPIキー節を参照)、長時間・広範囲にサイトを巡回している単一IPを見つけたら、スキャナー断定の前に「これはご自身のアクセスですか?」と確認するのも有効。

## 報告フォーマット

以下の形式でまとめる(数字は毎回変わるので都度取得すること、過去の値を使い回さない)。

```
## アクセス状況(<日付>、UTC <開始>〜<終了>時点=日本時間 <開始>〜<終了>)

| 項目 | 日次集計(簡易フィルタ) | 既知のノイズ除外後 |
|---|---|---|
| 実アクセス | X | Y |
| ユニークIP | X | Y |

- <ページ内訳・深いページへの到達有無の要約>
- <X経由の流入の有無>
```

前回セッションでの数値と比較できると良いが、正確な比較には毎回このスクリプトで取り直した最新の値を使う。

# Xでのリプライ宣伝(princess-tower)

`@princess_tower8`から、クラロワのランキング系投稿に**リプライ(返信)**でサイトを紹介する。
リポスト・引用ではなく返信であること、**投稿直前に必ずユーザーの最終確認を取る**ことが前提(2026-09-22にユーザーが指示)。

このサイトの最大の差別化は「**タグを知らなくても名前でプレイヤーを検索できる**」点なので、
リプライには必ず**相手本人のプレイヤー詳細ページのリンク**を載せ、ただの宣伝文にしない。

## 手順

### 1. 候補をXで検索する

ブラウザツール(`claude-in-chrome`)で以下を開く。`f=live`が最新順、`f=top`が人気順。

```
https://x.com/search?q=%23クラロワ ランキング&f=live
https://x.com/search?q=%23ClashRoyale ranking&f=live
https://x.com/search?q=%23ClashRoyale ranking&f=top
```

- 日本語の`#クラロワ ランキング`は**件数が少なく数週間前の投稿しか出ないことが多い**。英語・スペイン語圏の方が母数が大きい。
- **複合語クエリで足りないときは`#クラロワ`単体のLatestを見る**。数十分〜数時間前の投稿が並び鮮度が圧倒的に高い(2026-09-21の実測)。日本語圏は質問ではなく「トロ13000行った」「26000勝」のような**実績報告**が主流なので、ランキング以外でもこの型は本人特定ができて相性がよい。
- `get_page_text`は先頭1件しか拾えないことがある。**スクリーンショットを撮ってスクロールしながら読む**のが確実。
- 投稿のURLは`find`ツールで「投稿の日時リンク(status permalink)」を探すとまとめて取れる。

**必須条件: 表示回数(Views)が1,000回以上の投稿に限る**(2026-09-22にユーザーが決定)

リプライは1日数件までに抑える前提なので、**その少ない枠を誰にも見られない投稿に使わない**ため。

- 検索結果の一覧では、各投稿の下部にある**棒グラフのアイコンの横の数字が表示回数**(`139`・`2.6K`・`15K`など)。ここで1,000未満を先に落とせば、投稿を1件ずつ開かずに絞り込める
- 投稿の詳細ページでは日時の横に`1,960 Views`の形で出る。**送信直前にこの数字を必ず確認する**
- `K`表記は千単位(`2.6K`=約2,600)。`1K`未満の表記(3桁の数字)はその場で除外する

**良い候補**(この順で優先)
- 本人のランク・順位の報告(「○位に載ってた」「TOP 1 SPAIN」など)。祝意を述べたうえでリンクを出せるので、宣伝色が薄まる
- ランキングのスクリーンショットが貼られていて、**プレイヤー名が読み取れる**もの

**避ける候補**
- 他のクラロワ統計サイト(`clashroyale.last-dragon.work`・`claroy.rakda3.net`・CRTracker等)の宣伝投稿。競合の投稿に自サイトを貼る形になる
- 公式・大型アカウント(クラロワ公式、CRL関連)の告知。話題を乗っ取る形になる
- カードの強さランキングなど、プレイヤーを特定できない投稿(リンクを出す口実がない)

### 2. 投稿者のプレイヤータグを特定する

**名前検索を先に試す**(`lang`は相手の言語に合わせる)。

```bash
curl -s -G "https://princess-tower.duckdns.org/player/search" \
  --data-urlencode "q=<プレイヤー名>" --data-urlencode "lang=ja" -o r.html
grep -oE 'href="/player/[0-9A-Z]{3,15}"' r.html | sort -u
```

**⚠ 名前検索が空振りする主な原因**

- **ゲーム内の名前には全角記号が使われる**。`CR｜Malgret`は全角の`｜`(U+FF5C)で、ASCIIの`|`で検索しても出ない。`VosS シ`のように**カタカナが装飾記号として使われている**こともある。スクリーンショットの見た目だけで文字を決め打ちしない
- 検索は**完全一致＋前方一致**なので、`CR｜Malgret`に対して`Malgret`では引けない(先頭が`CR`のため)
- そもそも索引(929万件)に未収録の場合がある

**空振りしたらクラン経由で特定する**(この手順が最も確実)。プレイヤーカードのスクリーンショットにはたいていクラン名が写っている。

```bash
# 1) クラン名で検索してタグを得る(部分一致で大量に出るときは短いキーワードで絞る)
curl -s -G "https://princess-tower.duckdns.org/clan/search" \
  --data-urlencode "q=<クラン名>" --data-urlencode "lang=ja" -o c.html
grep -oE '<bdi>[^<]+</bdi>|#[0-9A-Z]{3,15}' c.html

# 2) メンバー一覧から本人を探す(全角記号込みの正確な名前もここで確認できる)
curl -s "https://princess-tower.duckdns.org/clan/<クランタグ>?lang=ja" -o m.html
grep -oE 'href="/player/[0-9A-Z]+"|<bdi>[^<]+</bdi>' m.html | grep -iB1 "<名前の一部>"
```

**同名が複数出た場合**(`VoSS`で3件など)は、どれが本人か決められないのでクラン経由に切り替える。
誤ったプレイヤーのリンクを貼るのは相手に失礼なので、**特定できなければリンクを載せない**(または候補から外す)。

最後に**リンクが実際に開けることを必ず確認する**。

```bash
curl -s "https://princess-tower.duckdns.org/player/<タグ>?lang=ja&from=xreply" -o p.html -w "HTTP %{http_code}\n"
grep -oE '<title>[^<]*</title>' p.html   # 名前が想定どおりか確認
```

### 3. リプライ文を作る

- **相手の言語で書く**。サイトは8言語対応なので`?lang=`も合わせる(`ja`/`en`/`es`/`pt`/`de`/`fr`/`it`/`ru`)
- **URLには必ず`?from=xreply`を付ける**(`?lang=es&from=xreply`のように連結)。自分の投稿は`?from=x`なので、**リプライ経由の流入を切り分けるために値を変えている**(2026-09-21に確立。`サイト宣伝方法.md`の「2026-09-21(追記4)」)。効果測定は`access-check`スキルでこの値を集計する
- **`&lang=`は必ず付ける**。付けないとOGPカードの説明文が英語で出る(Xのクローラーは`Accept-Language`を送らないためサイト既定の英語になる)。日本語の返信に英語の説明が付くのは不自然
- 構成は「①相手の成果への言及 → ②サイトの説明を一言 → ③本人のページのリンク → ④見られる内容＋非公式である旨」
- **Supercellの非公式ファンサイトである旨を必ず入れる**(商標・ファンコンテンツポリシー対応。`進捗ログ.md`フェーズ1.50)
- 文字数はXの上限280(日本語など全角は1文字=2)。URLは一律23文字として数える

日本語の例:
```
257位おめでとうございます🎉
名前でプレイヤーを検索できるサイトを作っていて、CR｜Malgretさんのページも出せます👇
https://princess-tower.duckdns.org/player/UJ9QP2RL8?lang=ja&from=xreply

使用中のデッキ・対戦履歴・連勝記録まで見られます(Supercell非公式のファンサイトです)
```

スペイン語の例:
```
¡Enhorabuena por el TOP 1 de España! 🇪🇸

Hago una web para buscar jugadores por nombre, sin la tag. Perfil de VosS シ 👇
https://princess-tower.duckdns.org/player/QC9YRJUR0?lang=es&from=xreply

Mazo actual, historial de batallas y rachas. Web de fans, no oficial.
```

### 4. ユーザーの最終確認を取る(必須)

元投稿の要約・**表示回数**・特定したプレイヤーとタグ・リプライ全文を提示し、`AskUserQuestion`で確認する。
**確認なしに送信しない。**

あわせて伝えるべき注意点:
- **面識のない相手への宣伝リンク付きリプライは、件数が増えるとXにスパム判定されやすい**。1日数件程度に留める
- 元投稿が他アカウントを@メンションしている場合、**返信はそのアカウント全員に通知が飛ぶ**(実例: 8アカウント)。送信前に`Replying to ...`の表示を読んで件数を伝える

### 5. 送信する

元投稿のURLを開き、**ツイート詳細ページ下部のインライン「Post your reply」**を座標クリックして入力し、`Reply`を押す。
(投稿ダイアログを開く方式は使わない。インライン方式ではフォーカス喪失の誤爆が起きていない。)

**⚠ 過去にハマった点(`進捗ログ.md`フェーズ1.55)**

- **投稿欄にフォーカスが無い状態で文字を送ると、Xのキーボードショートカットとして解釈される**(`l`=いいね、`t`=リポストなどが誤爆する)。
  必ず①スクリーンショットで座標を確認してクリック →②**短い1語だけ入力してフォーカスを確認**(`Replying to @xxx`が出ているか)→③残りを流し込む、の順で進める
- 先頭に`¡`などの記号が要る言語では、フォーカス確認用の文字を打った後に`ctrl+a`で選択してから全文を入れ直すとよい
- **インラインの`Reply`は1クリックで送信できている**(2026-09-21・09-22とも)。一方、自分の投稿を出す**投稿ダイアログの`Post`は1回目が効かないことがある**。いずれも押下後は必ずスクリーンショットで`Your post was sent.`を確認し、出ていなければもう一度押す

### 6. 記録する

- **詳細は`サイト宣伝方法.md`に追記する**(返信先・表示回数・本人特定の経緯・文面・分かったこと)。宣伝運用の知見はこのファイルに集約されている。**着手前にも直近の追記を読むこと**(同じ調査を繰り返さないため)
- `進捗ログ.md`には短いフェーズ項目として残し、詳細は上記ファイルを参照させる(フェーズ1.55と同じ書き方)
- 効果は後日`access-check`スキルで`?from=xreply`の件数を見て確認する。X経由のクリックには`Referer: https://t.co/`も付くので併せて見るとよい

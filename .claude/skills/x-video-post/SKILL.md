# 動画を作ってXに投稿する

ユーザーのプレイ動画(編集済みのクリップ)から、X向けの縦動画を日英2本作り、`@princess_tower8`から投稿する。
初回は2026-10-10の「トルネでキング起動 7選」(`Xポスト案.md`の案44)。ユーザーの評価は「素晴らしい」「すごくよかった」で、この流れと見せ方をそのまま型にしている。

流れは 1.素材を調べる → 2.1つずつ質問 → 3.全文で確認 → 4.作って確かめる → 5.投稿文 → 6.投稿 → 7.記録。
「作るだけ」「作った動画を投稿するだけ」の依頼なら、該当するところから始める。

**着手前に読む**: `X運用記録.md`の「投稿の操作(ブラウザ)」(特に「動画の添付」)と直近の記録、`Xポスト案.md`の冒頭の決まりごとと案44。投稿文の決まり(URLの`&lang=`と`from=x`、ハッシュタグは`#クラロワ #ClashRoyale`の両方、Supercell非公式の表示、Postは1回目が効かないことがある)は`x-post`スキルと共通。

## 0. 準備(セッションごと)

ffmpegはPCに入っていない。スクラッチパッドに仮想環境を作り、ffmpeg同梱の`imageio-ffmpeg`とPillowを入れる(30秒ほど。システムには入れない)。

```powershell
python -m venv <スクラッチパッド>\venv
<スクラッチパッド>\venv\Scripts\python.exe -m pip install -q imageio-ffmpeg pillow
```

以下の`video.py`・`xcount.py`は、この仮想環境のPythonで`.claude\skills\x-video-post\scripts\`から動かす。Pythonのコードをヒアドキュメントで渡すとバックスラッシュが壊れるので、使い捨ての処理もWriteでファイルにしてから動かす。

## 1. 素材を調べる

- 素材は`C:\01_fukuchi\01_norio\12_趣味\02_クラロワ動画\<日付_テーマ>\`。`01_org`が録画そのまま、`02_編集済み`がユーザーの切り出したクリップ(**こちらを使う**)。完成品は`03_X投稿用`を作って置く。
- `video.py probe <02_編集済み> <スクラッチパッド>\probe`で、各クリップの長さ・解像度・音声・音量と、1.5秒ごとのコマを並べた画像が出る。画像をReadで見て、各クリップで何が起きているか(敵のカード、どこで何を使ったか)を掴む。
- **ファイル名のカード名は略称や言い間違いがある**(初回は「エリジャイ」がエリクサーゴーレム、「盾戦」が盾の戦士だった)。映像で確かめ、公式の日本語名は`src/main/resources/messages_ja.properties`の`card.<英語名>=`、英語名はそのキー(公式APIの名前)を使う。判断の根拠(「ピンクの体が分裂してエリクサー0.5が出る」など)は質問に添えて確かめてもらう。
- 画面の上部に相手側の名前・クラン・トロフィーが映る(初回はユーザーの別アカウント`yyama888`)。
- 誘導先の候補はカード詳細`/card/<ID>`と、そのカード入りのデッキ画面`/decks?card=<ID>`。数字は、カード詳細の「使用人数 〇人中〇人」から取る。

## 2. 質問する(1つずつ)

ユーザーは「必要なことを、一つずつ順番に質問して」と頼む人。`AskUserQuestion`で1問ずつ聞き、推奨を先頭に置く。下の表の「前回の決定」を推奨にしてよい。全部を聞くよう言われていなければ、前回の構成をまとめて見せ、変えたい点だけ聞く。

| 順 | 決めること | 前回(10/10)の決定 | 補足 |
|---|---|---|---|
| 1 | 狙い | 攻略Tips+最後にサイトへ誘導 | 冒頭をサイトのデータにする案もあるが、文字だけの冒頭は飛ばされやすい |
| 2 | 長さ | クリップをほぼそのまま(約100秒) | Xの上限は2分20秒・512MB。45〜60秒への凝縮を推奨したが、ユーザーはそのままを選んだ |
| 3 | 言語 | 日本語版と英語版の2本 | 映像は同じで文字だけ替える |
| 4 | テロップ | カード名だけ | コツも入れるなら、案を全文で確認してもらう |
| 5 | 表記 | 公式名 | 英語版は公式の英語名 |
| 6 | タイトル | 「トルネでキング起動 7選」/「Tornado King Activation × 7」 | 「キンキ」は通じない人がいるので「キング起動」 |
| 7 | 上部の名前 | 帯で隠す | |
| 8 | 音 | ゲーム音のまま、音量をそろえる | BGMはユーザーが用意した著作権フリーの音源だけ |
| 9 | 誘導先 | そのカード入りのデッキ画面 | 「じゃあ何と組む?」にそのまま答えられる |
| - | 添付 | 10MB未満の軽量版を自動で添付 | ユーザーが選んだので、次からは聞かなくてよい |

## 3. 全文で確認する

構成(区間と長さ)、帯の文字(全クリップ分・日英)、エンドカードの文字を、返答の本文にコードブロックで全部出し、ターンを終えて返事を待つ(`AskUserQuestion`のpreviewは長文が切れる)。

**「まだ作っていません。この内容でよければ作ります」とはっきり書く。** 初回は確認待ちで止まっていたのに、ユーザーは作り終えたと思って「作ったフォルダが見つからない」と聞いてきた。返事が「作ってほしい」という意味なら、そのまま作る。

## 4. 作って確かめる

1. `assets/example_config.json`(初回の設定)をスクラッチパッドにコピーして書き換える。`src_dir`・`out_dir`・`work_dir`、`clips`(ファイル名と日英のカード名。並び順が動画の順)、`langs`(タイトル・エンドカードの2行・非公式の文・出力ファイル名)。非公式の文はサイトのフッター(`footer.unofficial`)と同じ文面にし、日本語は読点の後で改行(`\n`)して1文字だけの行を作らない。
2. `video.py images <config>` → `video.py preview <config>`。**出てきた画像をReadで見る**:
   - 帯が上部の名前・残り時間を隠し、キングタワーにかかっていない(素材の構図が違えば`band_height`で調整)
   - カード名が帯に収まっている(長い名前は自動で小さくなる)
   - エンドカードのURLと非公式の文が読める
3. `video.py render <config>`(2本で数分)→ `video.py verify <config>`。数字と画像の両方を確かめる:
   - 映像と音声の長さが一致している(音ズレが無い)。音量は-17 LUFS前後、ピークは-1 dBTP以下
   - 1コマ目にタイトルと「1/N カード名」が出ている(**Xのサムネイルになるので、1本目のカード名はフェードさせない**。初回は一度ここを落とした)
   - つなぎ目でカード名が切り替わり、最後にエンドカードへ移る
4. 完成品のフルパスを伝え、フォルダをエクスプローラーで開く。見た目は実際の描画まで確かめてから報告する。

見せ方の理由(変えるときの判断材料):
- 冒頭に別のタイトル画面を入れない。Xは最初の1〜2秒で読み飛ばされるので、1コマ目からプレイを見せる
- 帯は最初から最後まで出す。途中から見た人にも内容が分かり、1コマ目がそのままサムネイルになる
- エンドカード(4秒)には人数を入れない。日々変わるので、数字は投稿文に書く

## 5. 投稿文を作る

主役は動画なので、本文は「何の動画か」「世界上位で何人が使っているか」「リンク」に絞る(型は`Xポスト案.md`の案44)。

- 人数は投稿の直前にカード詳細から取り直す。シーズン開始直後は、デッキ画面に前のシーズンで集計している旨の注記が出ていないかも見る。
- URLは`/decks?card=<ID>&lang=ja&from=x`(英語版は`&lang=en&from=x`)。英語の「ランク戦」はサイトの表記どおり「Rank Battle」。
- 本文をファイルに書き、`xcount.py <ファイル>`で280以内か数える(初回はXのカウンタと一致した)。
- **リンクが開けるかの確認は`from=x`を外したURLで行う**(付けたまま開くと、流入の集計に自分のアクセスが混ざる。初回は2件混ざった)。
- 投稿をユーザーが頼んでいれば、文面の事前確認は要らない(`x-post`の方針の範囲内)。頼まれていなければ、文面を全文で見せて確認する。

## 6. 投稿する(Chrome)

Chromeは別のセッションと共有している(`CLAUDE.md`)。自分で作ったタブだけを使い、クリックの前にはスクリーンショットで画面を確かめる。

1. **軽量版を作る**: `video.py light <config>`。`<リポジトリ>\target\x-upload\x_upload_<言語>.mp4`(720×1280、2パスで約9.3MB)ができる。Chrome拡張の`file_upload`は1回10MBまでで、このセッションが読めるフォルダ(リポジトリ)のファイルしか渡せないため(素材フォルダやスクラッチパッドは拒否された)。`target/`はgitの管理外。縮めても見た目の差はほとんど無かった。
2. 自分のタブを作り、`https://x.com/compose/post`を開く。
3. **タブが前面にあるかを確かめる**(JSで`document.visibilityState`)。`hidden`なら、ユーザーが同じウィンドウで別のタブを見ている。Chromeは裏のタブの動画の読み込みを後回しにするので、Xが「Preparing media...」のまま進まない。ユーザーのタブを勝手に切り替えず、`AskUserQuestion`で「Claudeのタブグループの『Home / X』タブを前面にしてください」と頼む。
   - 一度止まった添付は、前面にしても戻らず、Readyになっても`Post`が押せないままだった。ダイアログを閉じて「Discard」で下書きを破棄し、開き直してやり直す(前面なら10秒ほどでReadyになった)。
4. 本文を入れる: 入力欄をスクリーンショットの座標でクリックし、JSで`document.activeElement`がダイアログ内の`tweetTextarea_0`かを確かめてから、貼り付けイベントで入れる(`type`は日本語が化けることがある)。
   ```js
   const el = document.activeElement;
   const dt = new DataTransfer(); dt.setData('text/plain', "<本文。改行は\n>");
   el.dispatchEvent(new ClipboardEvent('paste', {clipboardData: dt, bubbles: true, cancelable: true}));
   ```
   読み直すときは、URLの`?`・`=`・`&`を別の文字に置き換えて返す(そのままだと`[BLOCKED]`になる)。空行が2つに見えるのは入力欄の作りのせいで、実害は無い。
5. 動画を添付する: `find`でダイアログ内の「Add photos or video」の**file input**を探し、`file_upload`で軽量版を渡す(アイコンはクリックしない。OSのファイル選択画面が開いて操作できなくなる)。JSで、「`<ファイル名>: Ready`」の表示と`[data-testid=tweetButton]`の`aria-disabled`が外れるのを待つ。1回のJSは30秒以内で区切る(45秒で打ち切られる)。
6. スクリーンショットで本文・動画のサムネイル・残り文字数を確かめ、`Post`を押す。
7. **ダイアログが残っても押し直さない**。自分用の別タブでプロフィール(`https://x.com/princess_tower8`)を開き、上から数件の投稿を確かめる。投稿されていなければ確認用のタブを閉じ、元のタブで押し直す(初回は日英とも1回目が効かなかった)。
   ```js
   [...document.querySelectorAll('article')].slice(0, 5).map(a => ({time: a.querySelector('time')?.getAttribute('datetime'), href: a.querySelector('time')?.closest('a')?.getAttribute('href'), text: (a.querySelector('[data-testid=tweetText]')?.innerText || '').slice(0, 40), video: !!a.querySelector('video, [data-testid=videoPlayer]')}))
   ```
   先頭は固定ポスト。投稿直後は一覧に出ないことがあるので、出なければURLを変えて(`?r=1`など)読み込み直す。
8. 2本とも終えたら、プロフィールで**それぞれ1回だけ・動画つき**で載っていることを確かめ、投稿のURL(`/princess_tower8/status/<ID>`)と時刻(UTCなので日本時間に直す)を控える。
9. 片付け: 自分のタブを閉じ、`target\x-upload`を消す。

## 7. 記録する

- `X運用記録.md`の単独ポストの表に1行(日本時間・内容・数字1つ・メモ)。次にも効くハマりは「投稿の操作(ブラウザ)」に足す。
- `Xポスト案.md`の案44の〔最終 日付〕を直す。
- `.md`だけの変更なのでmasterに直接書き、変えたファイルだけを指定してコミットし、pushする。
- 見せ方で新しく決めたこと(ユーザーが前回と違う選択をしたなど)は、このファイルの「2. 質問する」の表を更新する。

# ユーザタグ収集の巡回バッチ状況確認(clash-royale-api)

本番VM上でSpringの定期実行が行うクラン/プレイヤーの巡回(`Crawler`)が`inbox`にタグを書き溜め、
毎時5分(UTC)の整理バッチが`by-tag`(正本)・`by-name`(名前検索用)に反映する。詳細は`CLAUDE.md`
(「プレイヤー名の蓄積先」「巡回と整理バッチ」節)を参照。

⚠ **`by-tag`は常に固定1024ファイルに分割される構造**なので、ファイル数(=1024)は保存タグ数ではない。
必ず全ファイルの**行数の合計**を人数として使う(2026-09-21にファイル数をそのまま人数として報告し誤った)。
`by-name`はほぼ`by-tag`と同数になる(全プレイヤーは必ず名前も取得できるため)ので、毎回両方は数えない。

## 手順

1. `scripts/check-crawler.sh`をBashツールで実行する(引数なし)。
   ```
   bash "C:\dev\clash-royale-api\.claude\skills\crawler-status\scripts\check-crawler.sh"
   ```
   サービス状態・設定、保存済みタグ数(by-tag全行数)、inbox未整理行数、直近の巡回進捗ログ、
   直近1時間のクロール関連エラー、現在時刻(UTC)をまとめて取得する。

2. 確認ポイント:
   - `CRAWLER_ENABLED`が`true`か、サービスが`active`か
   - 進捗ログのタイムスタンプ間隔から巡回ペース(クラン・プレイヤーの増分/経過時間)を出す
   - `inbox`が前回より極端に増え続けていたら整理バッチの異常を疑う
   - エラー欄は「巡回自体の例外」だけを見る(脆弱性スキャナー由来のノイズは無関係なので無視)

3. ログはUTCなので、報告時は日本時間を併記する(例: 「17:07 UTC(日本時間 翌2:07)」)。

## 報告フォーマット

一番知りたいのは「現在何人分のタグが保存されているか」なので先頭に出す。

```
## 巡回バッチの状況(<日付> <UTC時刻>時点 = 日本時間 <時刻>)

**保存済みタグ数: <by-tag全行数>件**(inbox未整理: <inbox行数>件)

- サービス: <active/inactive>、CRAWLER_ENABLED=<値>
- ペース: 約<X>クラン・<Y>プレイヤー / <分>分(直近ログより)
- <異常があれば一言、なければ「異常なし」>
```

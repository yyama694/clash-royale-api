# サイトの情報のファクトチェック

画面に出している情報が実態と合っているかを確かめ、おかしい箇所を`TODO.md`に記録する。**コードは変えない**。

## 2つの観点を分けて確かめる

1. **転記の正確さ**: 公式APIの値や計算結果が、画面にそのとおり出ているか(`compare_player.py`・`compare_pages.py`)
2. **値の意味**: 公式APIの値そのものが、画面のラベルどおりの意味か(`semantics.py`)。**問題が見つかるのはほぼこちら**

2026-09-29の実施では、1は全項目が正確だったのに、2で「世界1位が258連勝中」のような大きな誤りが見つかった。**「APIの値をそのまま出している」ことは正しさの保証にならない**。値の意味は、対戦履歴などの独立した別のデータと突き合わせて確かめる。

## 手順

### 0. 前回までの結果を読む

- `TODO.md`の「サイトの情報のファクトチェック」節(未対応の項目)
- 下の「確かめる項目と照合先」の表(直近の結果)
- 詳しい経緯は`archive/進捗ログ_2026-09.md`のフェーズ1.90(文言)・1.99・1.103(数値)と、`進捗ログ.md`のそれ以降のファクトチェックのフェーズ

既知の問題は新しい発見として報告し直さず、**直ったか・まだ残っているか**だけ確かめる。

### 1. サンプルを集める(数分)

```bash
PYTHONIOENCODING=utf-8 python .claude/skills/fact-check/scripts/collect.py <作業ディレクトリ>
```

- 作業ディレクトリはセッションのscratchpad(リポジトリの外)。約40MBのJSONができる
- ランク戦の世界上位40人・日本上位15人・クラン経由・育成途中の層、計140人ほど。各人に層(`tier`)を記録する。**上位勢だけで結論を出さない**(フェーズ1.90の教訓: 「APIが全カードを含む」は上位勢だけを見た誤った結論だった)
  - 「クラン経由」はクラン名の検索で強いクランに偏り、最低でも1万トロフィーほどになる。そのため「育成途中」はクランスコアの低いクランから別に拾う(フェーズ1.103の教訓: キングタワーレベル0とカードの所持枚数は、この層でしか見えなかった)
- `/cards`の全カードも`cards.json`に保存する(カードコレクションの照合に使う)
- 公式APIのトークンは`config/application-local.yml`から読む(環境変数`CLASHROYALE_API_TOKEN`があればそちらを優先)。**403ならローカルのグローバルIPがAPIキーの許可リストから外れている**(`CLAUDE.md`の「Clash Royale API連携に関する注意点」)

### 2. 値の意味を照合する

```bash
PYTHONIOENCODING=utf-8 python .claude/skills/fact-check/scripts/semantics.py <作業ディレクトリ>
```

連勝・連敗(参考。画面は10/1から使っていないAPIの値の記録)、14,000到達者のトロフィー、勝敗判定(デュエルはラウンドの勝ち数)、ランク戦の順位、最高シーズン、キングタワーレベル0、カードの所持枚数、苦手カードの勝率、対戦ごとの増減(次の対戦の`startingTrophies`・今のレーティングとつながるか)、ランク戦のリーグ、デュエルの勝者のラウンド数、対戦種別の内訳を、別のデータと照合して件数で出す。

- 勝敗判定では、引き分けでトロフィー・レーティングが動いた対戦を食い違いに数えず別に出す。ランク戦の0-0の引き分けは両者ともレーティングが下がるため(フェーズ1.103で確認。画面の「引き分け」は正しい)
- 「最新の対戦の後の値が今のレーティングと一致」の不一致が1〜2人なら、取得の直前の対戦(プレイヤー情報への反映が遅れる)を疑う。対戦の時刻を見る

### 3. 画面への転記を突き合わせる

```bash
PYTHONIOENCODING=utf-8 python .claude/skills/fact-check/scripts/compare_player.py <タグ> <タグ> ...
PYTHONIOENCODING=utf-8 python .claude/skills/fact-check/scripts/compare_pages.py
```

- `compare_player.py`: 本番のプレイヤー情報画面(英語表示)と同時刻のAPIの値を、項目ごとに比べる(得意/苦手カード、対戦履歴の相手の平均カードレベル、各行のスコア・増減・リーグ、消費漏れの中央値も自前で計算して比べる)。最新の対戦と最新のデュエルは対戦詳細画面も開いて比べる。タグは手順1の対象から、上位勢・14,000到達者・通常のトロフィー戦・デュエルの多いクラン対戦勢・育成途中の層を混ぜて10〜15人選ぶ
- `compare_pages.py`(数分): 世界と日本の個人・クランランキングの並び、上位20クランのクラントロフィー、シーズンの最終順位、ランキングの動きの増減(間のランク戦の`trophyChange`の合計と比べる)、トッププレイヤーのデッキが実在するか、デッキ画面の全デッキの平均エリクサーなど、カード詳細の使用率・人気順位・一緒に使われるカード(デッキ画面の全ページから数え直す)、人気のデッキ(同じく束ね直す)、デッキの勝率画面の条件と並び、クラン4件(世界・日本の上位と世界1位のクラン)の参加条件・メンバー一覧・世界順位のバッジ・クラン対戦成績・クラン対戦の参加状況。名前検索の候補は`name_search("Light")`などを個別に呼ぶ
  - クラン対戦の参加状況は、攻撃のある日(木〜月の10:00 UTCまで。`periodType`が`warDay`・`colosseum`)だけ表の数字を比べる。ほかの日は画面の案内が出ているかだけ見る。10/19(月)に初めて攻撃のある日に動かし、表と「今週まだ攻撃していないメンバー」の欄の両方が読めた
  - 世界順位のバッジは15分ごとの記録から出すので、今のランキングAPIとは数人ずれる。ずれたら、VMの最新の記録(`/var/lib/clash-royale-api/player-index/ranking-history/global/<日付>/<時刻>.tsv`)と比べる
  - 個人ランキングの「24時間」の列は、画面の順位(今のランキング)と、最新の記録の24時間前以降で最も古い記録の順位の差。確かめるときは、その記録をVMから取って比べる(10/19は1000行で一致)
- `compare_files.py`: VMのデッキ集計のファイルで、使用率ランキングの約1週間前からの増減、デッキの勝率画面の載せる条件(1人の対戦が3割以下を含む)と数えた対戦の数、カード詳細の「〇〇入りのデッキに勝っているカード」を数え直す。先にファイルを作業ディレクトリへ取る(`<日付>/<時刻>`はカード一覧画面の注記の日の`history/`の中を見る)。デッキ集計の途中(本番ログに`top deck collector: started`があって`collected`がまだ)なら、画面とファイルは前の回のままなので、そのまま比べてよい
  ```bash
  K="/c/Users/Norio Fukuchi/.ssh/oci_clash_royale_api"; D=/var/lib/clash-royale-api/player-index/card-usage; W=<作業ディレクトリ>
  for f in top-decks.tsv deck-win-rates.tsv; do ssh -i "$K" opc@161.33.136.175 "sudo cat $D/$f" > "$W/$f"; done
  ssh -i "$K" opc@161.33.136.175 "sudo cat $D/history/<日付>/<時刻>.tsv" > "$W/week-ago.tsv"
  mkdir -p "$W/top-battles"; ssh -i "$K" opc@161.33.136.175 "cd $D/top-battles && sudo tar cf - *.tsv" | (cd "$W/top-battles" && tar xf -)
  PYTHONIOENCODING=utf-8 python .claude/skills/fact-check/scripts/compare_files.py "$W"
  ```
- トップページの「〇万人以上を収録」は、`crawler-status`スキルの保存済みタグ数(`by-tag`の全行数)と比べる(スクリプトの対象外。VMへのSSHが要るため)
- 小数の丸め: 画面(Thymeleafの`formatDecimal`)は2進数の実際の値を丸めるので、APIの2.55は2.5と出る(2.5499…のため)。照合では`decimal.Decimal(x)`(`repr`を通さない)で丸める。使用率はJavaの`Math.round`(四捨五入)
- 本番サイトへのアクセスには`User-Agent: princess-tower-factcheck`を付けている。ビーコンは発火しないのでアクセス数(`access-check`)には数えられない
- サイトはAPIの応答を2分(個人・クランランキングは1分)キャッシュする。取得の間に対戦した人は戦績がずれうるので、1人だけのずれは取り直してから判断する

### 4. 文言を照合する(必要なとき)

画面の文言(10言語)にある事実(用語・カード名・注記の説明)は、フェーズ1.90と同じ方法で確かめる。

- ゲーム内の用語・カード名: ゲームデータの`texts.csv`(`HastyarSeamand/csv_logic-for-CR`)。ただし2025年10月時点で、2026年の新用語(キングタワーレベルなど)は無い。その場合はSupercell公式サポートポータルの記事タイトルなどで裏付ける(フェーズ1.98)
- 注記の説明(「公式APIでは〜できない」「毎週〜にリセット」など): 手順1のデータや実測で確かめる
- **訳の無いカード名・モード名**: 本番のログに`LabelResolver`の警告が出ている(辞書に無い値に初めて出会ったときに1回)。毎回数える。カード一覧に無いイベント専用カードは`MessagesConsistencyTest`では気づけない
  ```bash
  ssh -i "/c/Users/Norio Fukuchi/.ssh/oci_clash_royale_api" opc@161.33.136.175 \
    'sudo journalctl -u clash-royale-api --since "7 days ago" --no-pager -o cat | grep -oE "No ([a-z]{2} translation for card|label for game mode).*$" | sort -u'
  ```
  - 見つかったら`texts.csv`で訳を裏付けて足す。モード名は`game_modes.csv`の`Name`→`TID`→`texts.csv`の順に引く(フェーズ1.123)。ゲームデータに無いもの(2026年の新モードなど)は、今の「その他」のままにして記録する

## 報告のしかた

- 結論には**サンプルの人数と件数**を添える(「116人中102人」など)。「〜と推定」と「確認済み」を分けて書く
- 注記に「一致しないことがある」と書いてある項目こそ、**何人ずれているかを数える**。フェーズ1.19で「一致しない人もいた」と気づきながら数えなかったため、ほぼ全員ずれていることに気づくのが遅れた
- 実例は、画面で誰でも確かめられるプレイヤー(ランキング上位など)を選ぶ
